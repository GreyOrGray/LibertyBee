# Liberty Bee — Data Dictionary (48 tables)

**Audience:** a developer who needs to know what a table holds, who owns it, and who reads it — without reading DDL. Companion to [`engine_internals.md`](engine_internals.md) (the module reference), [`users_guide.md`](users_guide.md), and [`parameter_reference.md`](parameter_reference.md) (the knobs live in `reference.ParameterRegistryDefault` / `ParameterRegistryDefined`; each knob is documented there and carries its own Description in the database). Columns/types/PKs are from the live schema at V00059; purpose/owner/readers verified from the DDL migrations + module source.

> **Build status:** users_guide v2 (#141), Pass 3. Tables with no live writer/reader in `app/src` are marked **⚠ dormant** and consolidated in [`../v_0_3/phases/phase_1_9/engine_hygiene_findings.md`](../v_0_3/phases/phase_1_9/engine_hygiene_findings.md); several are *intentionally* retained (KD-locked for V2).

## How to read this

- **Run isolation:** every `simulation.*` table leads its primary key with `RunID` — thousands of Monte-Carlo runs share one database, and the compound `(RunID, …)` key is what keeps them separate. A query that omits `RunID` reads across runs.
- **Ledger vs master vs reference:** **ledger** = append-only, one row per event, carries an `EventID` (`Event`, `FundLedger`, the `*Ledger`/`*Step` tables); **master/state** = updated in place through an entity's life (`Lease`, `PropertyUnits`, `PropertyAcquisitionAttempt`); **reference** = static input restored from the `LibertyBeeGold` backup / seeded by migrations; **config** = the parameter store; **metadata** = env/migration bookkeeping.
- **Two `PropertyID` spaces:** `reference.Properties.PropertyID` (the market-pool ID, carried by `PropertyMarket`/`PropertyAcquisitionAttempt`/`Compliance*`) is distinct from `simulation.Properties.PropertyID` (a **run-scoped**, manually-assigned ID minted only once LB owns the property, carried by `PropertyUnits`). `compliance_manager` bridges the two via `simulation.Properties.AddressID`.
- **`EventID` is `BIGINT`** everywhere (widened INT→BIGINT at V00057, KD-008/#40) for overflow safety on long/large sweeps.

## 1. `simulation.*` — per-run state (31 tables)

### Run & audit
- **`Run`** (11) — the run-lifecycle anchor, one row per execution. **PK `RunID`.** Cols: `Status` (CREATED/RUNNING/COMPLETED/HALTED), `RandomSeed`, `RunType`, `SnapshotCadence`, `StartDate`/`EndDate`/`CompletedAt`, `Notes` (carries the HALTED death certificate). *Master.* Owner: `run_manager` (+ `simulation` sets `SnapshotCadence`). Readers: run_manager, event_logger, snapshot_manager, employee_manager, tenant_manager (seed), backfill, master_test_runner. *Note:* `ProjectionID` has **no FK** (KD-001/#33).
- **`Event`** (13) — the canonical append-only event log; every meaningful action writes one row (~50k+/run, the highest-volume table). **PK `(RunID, EventID)`.** Cols: `EventType`/`EntityType`/`ActionType` (the taxonomy), `EntityID`, `Amount`/`Currency`, `CausalTag`, `Metadata`, `MonthIndex`/`EffectiveDate`. *Ledger.* Owner: `event_logger` (the sole writer, used by all managers). Readers: master_test_runner, snapshot_manager, backfill. *Note:* `ParentEventID` dropped at V00054 (dead).
- **`RunSnapshot`** (26) — periodic cadence-boundary state capture for trajectory visibility. **PK `(RunID, SnapshotDate)`.** Col groups: fund balances, portfolio (units/occupancy), monthly aggregates (rent/OpEx/payroll), staff count, cumulative counts (terminations/evictions/turnovers), source (LIVE/BACKFILL). *Ledger-like.* Owner: snapshot_manager, backfill. Readers: those two (dup checks).

### Funds & macro
- **`FundLedger`** (18) — append-only ledger of every money movement across 5 buckets (Cash/CSF/EIP + CashHold & Escrow liabilities), each a debit/credit/post-balance triple. **PK `(RunID, EventID, LedgerDate)`.** *Ledger (never updated).* Owner: `fund_manager`. Readers: fund_manager (prior balance), snapshot_manager. *Note:* Escrow cols added V00013; PK widened at V00057.
- **`InflationSchedule`** (12) — the whole-run macro path, generated once up front. **PK `(RunID, MonthIndex)`.** Cols: `GeneralRate`/`RentRate`/`OpExRate`/`PropertyRate`, `VacancyDelta`, `WageGrowthRate`, `ScenarioType`/`ScenarioPhase`. *Config-like (write-once, read-only during the loop).* Owner: `inflation_engine`. Readers: inflation_engine (OpEx factor), property_market_manager (PropertyRate), tenant_manager (RentRate/VacancyDelta), income_model (WageGrowthRate). *Note:* rate cols widened to decimal(9,6) + VacancyDelta at V00050 (#48); WageGrowthRate added V00059 (Phase 1.8).
- **`GrantLedger`** (8) — ⚠ **dormant by design.** Grant application/decision ledger with **no engine code** (no `grant_manager.py`). Reserved for KD-022/#54; deliberately kept (V00054). No writer/reader in `app/src`.
- **`Payroll`** (8) — append-only bi-monthly per-employee payroll record. **PK `(RunID, PayrollID)`.** Cols: `EmployeeID`, `GrossPay`/`BenefitsCost`/`TotalCost`. *Ledger.* Owner: `employee_manager`. Readers: snapshot_manager (reconciliation).
- **`Employees`** (8) — per-run employee roster. **PK `(RunID, EmployeeID)`.** Cols: `RoleID`, `HiredDate`, `TerminatedDate` (nullable), `BaseSalary`/`BenefitsCost` (updated on raise), `IsActive`. *Master.* Owner: `employee_manager` (INSERT on hire, UPDATE on raise). Readers: employee_manager, snapshot_manager. *Note:* `TerminatedDate`/`IsActive=0` are **never written** — no termination path in V1.

### Property, market & compliance
- **`Properties`** (10) — one row per property LB owns, per acquisition event (supports sell/re-acquire). **PK `(RunID, PropertyID, EventID)`.** Cols: `AddressID` (→ `reference.Properties.PropertyID`), denormalized address/type, `AcquisitionDate`, `BasePrice`/`InflationAdjustedPrice`, `TotalUnits`. *Master.* Owner: `property_acquisition_manager`. Readers: simulation, employee_manager, compliance_manager, snapshot_manager. *Note:* PK gained `EventID` at V00007 (re-acquire support).
- **`PropertyUnits`** (13) — one row per owned unit; the occupancy/turnover state carrier. **PK `(RunID, UnitID, PropertyID, EventID)`.** Cols: `Beds`/`Baths`/`BaseRent` (set-once at acquisition), `UnitStatus` (Available/Occupied/Turnover/Pending_Move_Out/Compliance_In_Progress), `CurrentLeaseID`, turnover dates. *Master.* Owner: property_acquisition (INSERT), tenant/eviction/compliance/turnover managers (status UPDATEs). Readers: simulation (counts), tenant_manager, turnover, snapshot. *Note:* `TenantID` dropped V00056 (KD-014/#46), `CurrentRent` dropped V00058 (#154/#45/KD-013).
- **`PropertyMarket`** (12) — manual SCD-2 market-state history per market-pool property (Available/Listed/UnderContractLB/LBOwned/OtherBuyerOwned), old rows closed via `ExpirationDate`. **PK `(RunID, PropertyMarketID)`.** Cols: `PropertyID` (reference space), `MarketStatus`, validity window, `CurrentListingPrice`/`OriginalBasePrice`, `DaysOnMarket`, `HoldPeriodDays`. *SCD-2.* Owner/Readers: property_market_manager + property_acquisition_manager.
- **`PropertyAcquisitionAttempt`** (33) — one row per acquisition attempt, updated in place as the pipeline advances. **PK `(RunID, AttemptID)`.** Col groups: offer/negotiation, inspection/due-diligence, closing, outcome, pipeline state machine (`PipelineStage`/`IsActive`/timeouts). *Master.* Owner: property_acquisition_manager. Readers: compliance_manager. Carries **no** `EventID`.
- **`PropertyAcquisitionStep`** (8) — append-only per-transition ledger for the acquisition pipeline. **PK `(RunID, AttemptID, StepID)`.** *Ledger.* Owner/reader: property_acquisition_manager only. *Note:* PK corrected off IDENTITY at V00008 (IDENTITY breaks multi-run isolation).
- ~~`PropertyOnboarding` / `UnitOnboarding`~~ — **DROPPED at V00060** (release hygiene). Dead legacy static-onboarding tables, superseded by the compliance pipeline (`ComplianceAttempt.BuildingOnlineDate`); empty, no writer/reader.
- **`ComplianceAttempt`** (12) — one compliance cycle per building/unit (acquisition-triggered). **PK `(RunID, AttemptID)`.** Cols: `PropertyID`/`UnitID` (reference space), `ScopeType` (BUILDING/UNIT), `TriggerType`, `BuildingOnlineDate`/`UnitReadyDate` (milestone idempotency). *Master.* Owner/reader: compliance_manager only.
- **`ComplianceWorkItem`** (17) — the actual inspection/remediation actions with status flow; `ParentWorkItemID` links remediation to its failed inspection. **PK `(RunID, WorkItemID)`.** Cols: `WorkType`, `Status`, cost estimate/actual/paid, `Severity`, `Metadata`. *Master.* Owner/reader: compliance_manager only.
- **`ComplianceStep`** (8) — append-only narrative step ledger for compliance. **PK `(RunID, StepID)`.** *Ledger.* Owner/reader: compliance_manager only.
- **`TurnoverWorkOrder`** (20) — the 5-step make-ready workflow per vacated unit (SKIPPED rows kept for audit). **PK `(RunID, TurnoverWorkOrderID)`.** Cols: `LeaseID`/`UnitID`, `TerminationType`, `WorkItemType`, `WorkSequence` (1-5), `Status`, scheduling dates, `WasEviction`, `DamageWithheldAmount`. *Master.* Owner: turnover_manager. Readers: simulation (idempotency), snapshot_manager.

### Tenants & leases
- **`Household`** (11) — one row per household at lease signing; persists across lease turnover (household ≠ lease). **PK `(RunID, HouseholdID)`.** Cols: `HouseholdType`/`HouseholdIncomeBand`, `AdultCount`/`ChildCount`, `TCSRedemptionProbability`, `SigningMonthlyIncome` (Phase 1.10, V00063 — dollar income at onboarding, nullable/no-backfill; feeds `retention_model`'s affordability term via `income(t) = SigningMonthlyIncome × wage_growth(onboarding→t)`). *Master.* Owner: tenant_manager. Readers: tenant_credit_manager, lease_renewal_manager (retention).
- **`Person`** (9) — one row per resident (adult/minor). **PK `(RunID, PersonID)`.** Cols: `HouseholdID`, `DateOfBirth`, `IsAdult` (set once, minors never re-aged). *Master (append-only in practice).* Owner: tenant_manager (INSERT only). Readers: none in `app/src` (write-only; external reporting reads it). *Note:* surnames are drawn **per-person, not per-household** — a family can have mismatched last names (cosmetic; tenant-engine item).
- **`Tenants`** (10) — ⚠ **dormant.** Legacy pre-Household tenant model, 0 rows in V1. **PK `(RunID, TenantID)`** (added V00055). No writer/reader. Retained for V2 (KD-005/#37, KD-017/#49). *Note:* uniquely, `RunID` here is `INT`, not `BIGINT`.
- **`Vacancy`** (14) — every unit-vacancy lifecycle + the applicant-funnel counters. **PK `(RunID, VacancyID)`.** Cols: start/end/`LeaseID`, `DaysVacant` (computed), `TargetFillDate`, funnel counts (generated/self-screened/applied/rejected/selected). *Master.* Owner/reader: tenant_manager only.
- **`ApplicantEvaluation`** (11) — per-applicant decision ledger (the qualification funnel). **PK `(RunID, EvaluationID)`.** Cols: `VacancyID`, `Outcome`, `RejectionReason`. *Ledger.* Owner: tenant_manager (INSERT only). Readers: none in `app/src` (write-only audit trail).
- **`Lease`** (17) — the lease contract + its full state machine. **PK `(RunID, LeaseID)`.** Cols: `MonthlyRent` (immutable, at signing), `EffectiveMonthlyRent` (after reductions, NOT NULL by design), `CumulativeRentReductionPct`, `ConsecutiveMissedPayments` (eviction trigger), `RenewalDecision`, `LeaseStatus`. *Master (the busiest state table — 5 writer modules).* Owner: tenant_manager (INSERT), rent_collection/eviction/lease_renewal/rent_reduction managers (UPDATE). Readers: snapshot, tenant_credit. *Note:* CHK permits `RENEWED`/`EXPIRED` but nothing writes them (KD-024/#56).
- **`LeaseTermination`** (17) — one summary row per terminated lease (RENEWED gets none). **PK `(RunID, LeaseID)`.** Cols: `TerminationType`, financial rollup (arrears/deposit/penalty), eviction + async post-termination dates. *Master (updated by later async settlement).* Owner: eviction_manager + lease_renewal_manager (INSERT), security_deposit_manager (UPDATE settlement). Readers: rent_collection, tenant_credit, snapshot. *Note:* `NON_RENEWAL_TENANT` enum value is CHK-permitted but **never written**.
- **`LeaseTerminationLedger`** (10) — append-only per-event termination/turnover/deposit trail. **PK `(RunID, LedgerID)`.** Cols: `TxnType` (15-value CHK), `Amount`, `Metadata`. *Ledger.* Owner: eviction_manager + lease_renewal_manager. Readers: none in `app/src`. *Note:* only **7 of 15** `TxnType` values are ever written — the deposit/turnover/vacancy ones live in other ledgers; the rest are dead enum values.
- **`MonthlyPaymentStatus`** (11) — per-(lease, month) payment state. **PK `(RunID, LeaseID, BillingMonth)`** (a 3-part natural key). Cols: `CanPayThisMonth` (rolled once), `PaymentStatus` (ON_TIME/LATE/MISSED/REDEEMED), `ArrearsAmount`. *Master/state.* Owner: rent_collection_manager. Readers: lease_renewal (late count), tenant_credit (good standing). ⚠ *Note:* **no `CREATE TABLE` exists in any migration** — a genuine provenance gap (lives in Gold or an untracked script).
- **`RentCollection`** (13) — append-only per-collection-event log. **PK `(RunID, CollectionID)`.** Cols: `AmountCollected` (0 iff REDEEMED), `IsLate`, `LateFeeAmount`, `ArrearsAmount`. *Ledger.* Owner: rent_collection_manager (INSERT only). Readers: eviction (history), tenant_credit. *Note:* an earlier unused V00002 version was dropped/redesigned at V00011.

### Deposits & credit
- **`LeaseDeposit`** (15) — per-lease deposit state (FULL/INSTALLMENT, escrow, settlement). **PK `(RunID, LeaseID)`.** Cols: required/escrowed amounts, `DepositMethod` (immutable), installment progress, `Status`, settlement fields (V00021). *Master/state.* Owner: security_deposit_manager. Readers: security_deposit_manager, turnover_manager (damage state).
- **`LeaseDepositLedger`** (10) — append-only deposit-transaction trail; source of truth for the escrowed balance. **PK `(RunID, LedgerID)`.** Cols: `TxnType` (FULL_PAYMENT/INSTALLMENT_PAYMENT/REFUND/FORFEITURE/DAMAGE_WITHHOLD), `Amount`/`BalanceAfter`. *Ledger.* Owner/reader: security_deposit_manager.
- **`TenantCreditBalance`** (12) — materialized per-household TCS state (the fast eligibility cache). **PK `(RunID, HouseholdID)`.** Cols: `CurrentBalance` (cap enforced at runtime), `LifetimeAccrued`/`LifetimeRedeemed`, `AnnualRedemptionUsed`, `ExpiryStatus`, `CreditExpiryDate` (persisted computed = exit + 24mo). *Materialized state.* Owner/reader: tenant_credit_manager.
- **`TenantCreditLedger`** (11) — append-only TCS source of truth (ACCRUAL/REDEMPTION/FORFEITURE; TRANSFER reserved-unused). **PK `(RunID, CreditTransactionID)`.** Cols: `TransactionType`, `Amount`/`BalanceAfter`, related collection/lease FKs. *Ledger.* Owner/reader: tenant_credit_manager.

## 2. `reference.*` — static inputs (15 tables)

### Portfolio catalog
- **`Properties`** (17) — the 1,673 scraped Salem-MA properties. **PK `PropertyID`.** Cols: `Source`/`SourceID`, `LivingArea`/`YearBuilt`/`TotalUnits`, `BasePrice`. Readers: property_market_manager, property_acquisition_manager, compliance_manager.
- **`Units`** (8) — the 3,847 reference units. **PK `UnitID`.** Cols: `Beds`/`Baths`, **`BaseRent`** (Salem bedroom-median) **and `AdjustedRent`** (bathroom-count-adjusted). Readers: property_acquisition (BaseRent → PropertyUnits; AdjustedRent → yield scoring), compliance, employee_manager. *Note:* the #44/KD-012 + KD-040 columns; V2 plan = build `AskingRent` at sim time from `MedianRentData`.

### Parameters
- **`ParameterRegistry`** (7) — ⭐ **the canonical knob store** (unified EAV). **PK `ParameterID`**, unique `(Category, Name, ProjectionID)`. `ProjectionID` NULL = global, non-NULL = per-projection override. `DataType`-coerced, fail-loud. *Config.* Readers: `parameter_registry.py` (sole read path) → 12 manager modules. Full knob catalog → [`parameter_reference.md`](parameter_reference.md). **Projection inventory (post-V00062):** 321 global knobs + per-projection overrides for exactly **13 released projections** — the 10 `V1_Baseline_*` rungs (IDs 200–209, the frozen-corpus source) + 3 `Stress_*` scenarios (IDs 220–222, kept as adversarial configs). The retired V0.1/0.2 `PType_*` scenario-exploration grid (IDs 1–156, TCS 5% + 2× staff raises — *not* the released baseline) was **purged at V00062** (release hygiene, #114); the default `--projection-id` was repointed 1→206 in the same change.
- **`ParameterCategory`** (3) — controlled-vocab FK target for `ParameterRegistry.Category` (19 categories). **PK `Category`.** DB-side integrity only; no `app/src` SELECT. *Note:* the CSF description's "Capital Stabilization" trap mis-expansion was corrected to "Community Stability Fund" at V00053.
- **`ProjectionParameters`** (94) — ⚠ **legacy, KEPT + marked-for-retirement (V00061).** Pre-registry wide per-projection table; **zero live readers** (V00039 seeds the registry from literals, not a read of this table). Gray-ruled kept for now; its `RetireNote` extended property flags a clean post-1.0 drop.
- ~~`ProjectionConstants`~~ — **DROPPED at V00061** (release hygiene). Pre-registry constants; its rows were migrated into the registry MARKET category at V00053, then the table sat empty + unread.

### Domain parameter tables
- **`AcquisitionParameters`** (41) — the acquisition-pipeline config (single row). **PK `ParameterID`.** All 37 non-metadata columns are read by `load_acquisition_parameters` (offer/seller/inspection/negotiation/closing/capacity/timeout). The **~72 orphaned onboarding columns** (SmokeCO/Habitability/Lead/Unit/Leasing — read only by the retired `app/src_legacy/onboarding_manager`) were **dropped at V00061**; the 6 `RepairCost*Pct` cols went at V00053.
- **`ComplianceParameters`** (13) — per-WorkType compliance config (10 seeded WorkTypes). **PK `ParameterID`.** Cols: cost/duration bands, fail chance, contractor lag, blocking flag, `ScopeType`. All 12 non-PK cols actively read. Reader: compliance_manager.
- ~~`TenantParameters`~~ — **DROPPED at V00061** (release hygiene). Pre-registry `(ParameterName, ParameterValue)` catalog, value-migrated into the registry TNT/QUAL/LEASE/TIMING categories; no live reader (the same-named `tenant_manager` symbol is a Python dataclass, not this table).
- **`EmployeeRole`** (5) — static role catalog. **PK `RoleID`.** Cols: `BaseSalary`, `SalaryCap` (KD-029 raise clamp), `BenefitsCost`. Reader: employee_manager. *Note:* frozen doc's `configuration_loader` reader claim is stale (now registry-only).

### Name & person-seed pools
- **`FirstName`** (3) / **`LastName`** (2) — synthetic name pools for cosmetic tenant names. **PK `*NameID`.** Reader: tenant_manager (loaded once, sampled per person). ⚠ *Note:* **neither has a `CREATE TABLE` in any migration** — Gold-backup-only provenance (same pattern as `sp_CleanSimulationEngine`).
- **`PersonSeed`** (9) / **`PersonSeedRelationship`** (8) / **`SeedFamily`** (5) — ⚠ **dormant.** Family-composition template tables, created together in the oddly-numbered `V10000__seedFamily_tables.sql`. **Zero live readers** (household generation samples name pools directly). KD-004/#36 (V2-deferred).

### Other reference
- **`MedianRentData`** (5) — Salem median-rent-by-bedroom lookup; used at 2025-01-09 seed-build to derive `Units.BaseRent`/`AdjustedRent`. No PK; no live reader. Retained as the V2 `AskingRent` source (KD-012/#44).
- ~~`Calendar`~~ — **DROPPED at V00060** (release hygiene). Was a date dimension (`EmergencyMultiplier` etc.) with no live reader in `app/src`.
- **`Tenants`** (2) — ⚠ **legacy, dormant.** Pre-Household candidate pool. **PK `TenantRowID`** (added V00055, which also **dropped the synthetic `SSN` column** — "no place in a public release"). No reader; retained for V2 (KD-009/#41, KD-017/#49).

## 3. `dbo.*` — environment metadata (2 tables)

- **`_provenance`** (7) — self-describing stamp per ephemeral test DB (label, branch/commit, note). Written by `environmentscripts/migration_manager.py`, not a migration. Read by tooling only.
- **`SchemaVersion`** (5) — the migration-application ledger (one row per applied version). Written/read by `migration_manager.py` to compute the pending set. Not read by the engine.

## 4. Dormant / provenance-gap tables (summary)

Consolidated for the cleanup sweep in [`../v_0_3/phases/phase_1_9/engine_hygiene_findings.md`](../v_0_3/phases/phase_1_9/engine_hygiene_findings.md). **Intentionally retained** (KD-locked for V2): `GrantLedger` (KD-022), `reference.Tenants`/`simulation.Tenants` (KD-005/009/017), `PersonSeed`/`PersonSeedRelationship`/`SeedFamily` (KD-004), `MedianRentData` (KD-012). **Dropped (release hygiene, value-neutral):** `PropertyOnboarding`, `UnitOnboarding`, `reference.Calendar` (V00060); `reference.TenantParameters`, `reference.ProjectionConstants` + the 72 orphan `AcquisitionParameters` columns (V00061). **Dropped (V00070):** `reference.ProjectionParameters` — the retirement deferred past 1.0 at V00062, executed now that 1.0 has shipped. It was engine-unread but actively misleading: 163 rows including a stale $2.0M-$7.5M ladder and its own ID=206 row that had drifted from the registry's. **Split (V00071):** `reference.ParameterRegistry` became `reference.Projection` + `ParameterRegistryDefault` + `ParameterRegistryDefined`. **Provenance gaps** (exist live, no `CREATE TABLE` in the migration tree): `reference.FirstName`, `reference.LastName`, `simulation.MonthlyPaymentStatus`.
